# 22 个模块速查

`SKILL.md` 里的每个模块都写全了六段（目的 / 何时启用 / 操作步骤 / 关键提问 / 输出模板 / 示例）。这里是给已经会用的人看的索引：**什么时候该调哪个模块。**

---

## 七层总览

| 层 | 它回答的问题 | 模块 | 漏了会怎样 |
|---|---|---|---|
| **L1 框定** | 我们在解决什么？什么算成功？ | M1–M3 | 解对了错的问题 |
| **L2 拆解** | 方案靠什么成立？哪里最脆？ | M4–M8 | 攻击了空气，或漏掉承重点 |
| **L3 攻击** | 它会怎么死？ | M9–M12 | 只看到自己想到的风险 |
| **L4 人** | 谁会帮、谁会拦？ | M13–M14 | 方案在纸上成立，在一线变形 |
| **L5 时间资源** | 代价是什么？还能回头吗？ | M15–M17 | 赢了战役，输了机会 |
| **L6 认知** | 谁的脑子被骗了？ | M18–M19 | 用错误的证据支持正确的结论 |
| **L7 决策** | 那到底做什么？ | M20–M22 | 分析很精彩，然后没有然后 |

## 按症状选模块

不知道从哪开始，就从症状查：

| 你观察到的症状 | 先查 |
|---|---|
| 说不清"用户在什么场景下会用它" | M1 + M14 |
| 数字很漂亮，但总觉得不真实 | M7 + M19 |
| 所有人都说好，没人反对 | M9 + M19（群体极化、权威偏误） |
| 方案逻辑很顺，但你不安 | M5（承重假设没找到） |
| 做了很久，没什么进展 | M15 + M17（是不是该停） |
| 每个功能都合理，加起来不成立 | M1 + M20（解法堆砌，不是产品） |
| 团队都同意，但推不动 | M13 + M14（政治与执行） |
| 竞品一降价你就慌 | M12（护城河是假的） |
| 越做越不敢停 | M17 + M18（沉没成本） |
| 每次想到这事就焦虑 | 先处理情绪（§8.3），再进 M1 |

## 按决策类型路由

**Whether（做不做）**：M1 → M2 → M4 → M5 → M9 → M10 → M15 → M17 → M20 → M22

**How（怎么做）**：M3 → M8 → M14 → M11 → M20 → M21 → M22

**Which（选哪个）**：M2 → M12 → M15 → M17 → M11 → M20

**Rescue（已经出问题）**：M6（根因）→ M8（瓶颈）→ M13（谁在阻挠）→ M17（还能不能退）→ M20（怎么补救）

## 别用的时候

- 决策代价 < 一小时能挽回的：直接做，别分析
- 纯情绪倾诉：先共情，别上模块
- 信息严重不足：先补 3 个关键数字，再开工
- 用户已经决定、只要执行方案：做一次风险提示，然后转执行支持

**模块是手术刀，不是保健品。** 没问题的地方不要硬开刀。
